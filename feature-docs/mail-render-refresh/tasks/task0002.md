# Task Plan: task0002 — Markdown renderer and cool-palette mail styles

## Goal

The digest email renders each translated release body's Markdown as styled

## Requirements

## Design

### Renderer (markdown.go)

Contract: takes one release body (plain text containing Markdown), returns
an HTML fragment string with all styling inline. Never returns an error —
unclassifiable lines degrade to escaped plain paragraphs. Line-based
processing:

1. Fenced code block delimiters open/close a block; an unclosed block runs
   to the end of the input (SPEC FR1). Block content is escaped verbatim,
   never inline-parsed, never translated markup.
2. ATX headings (1–3 `#`) all map to the single sub-heading style
   (heading-body token; DESIGN.md "one heading level" decision).
3. Consecutive `- ` / `* ` lines form one unordered list; consecutive
   `N. ` lines form one ordered list; a blank or non-list line terminates
   the run.
4. Other non-blank lines accumulate into paragraphs; blank lines separate
   paragraphs.
5. Inline pass (applied to heading, list-item, and paragraph text, in this
   order of precedence): inline code spans (no further parsing inside),
   bold, links. Link hrefs must parse as URLs with scheme http or https —
   anything else renders as escaped plain text (NFR2).
6. Every text run is HTML-escaped BEFORE markup is added around it
   (escape-before-markup convention in IMPLEMENTATION.md).

### Styles (build.go)

All values literal, from design-system/tokens.yaml + DESIGN.md:

- Palette swap: primary #33658A, canvas #EDF1F5, on-surface #232A31,
  on-surface-muted #5C6B7A, divider #D9E1E8 (surface / on-primary #FFFFFF
  unchanged). No legacy warm hex may remain.
- Sub-heading: 16px/1.5 bold, on-surface, 24px top / 8px bottom margins,
  no top margin as first element.
- Paragraphs: 8px vertical margins. Lists: 24px left padding, 8px between
  items. Bold: weight 700.
- Inline code: monospace stack (ui-monospace, SFMono-Regular, Menlo,
  Consolas, monospace), 0.875em, surface-muted background, 1px 4px padding,
  3px radius.
- Code block: surface-muted background, 16px padding, 13px/1.6 monospace,
  4px radius.
- Links: primary color, underlined.
- Empty-body placeholder path unchanged (muted text, never dropped).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Each supported construct (heading, ul, ol, inline code, bold,
      http/https link, fenced block) renders to its styled HTML element;
      a mixed document renders in source order.
- [ ] AC-2: Unsupported constructs and Markdown-free text render as escaped
      plain paragraphs with no content loss; blank lines separate
      paragraphs and terminate lists.
- [ ] AC-3: Raw HTML in the body appears escaped in the output; non-http(s)
      link schemes are never emitted as hrefs.
- [ ] AC-4: An unclosed fenced block renders to the end of the body without
      error; fenced content is never inline-parsed.
- [ ] AC-5: The generated mail contains the new token values and NONE of
      the legacy warm hexes (#C15F3C, #F4F1EC, #2B2620, #6E675E, #E4DED4).
- [ ] AC-6: The empty-body placeholder and subject formats behave exactly
      as before (existing tests keep passing).

## Test Notes

Renderer tests (markdown_test.go) are pure input→HTML table tests covering
AC-1…AC-4. build_test.go covers AC-5/AC-6 plus integration of renderer
output into the digest. No network/SMTP involvement.

## Out of Scope

- Translation prompt (task0001). SMTP send path (send.go untouched).
- Nested lists, tables, blockquotes, images — degrade to plain paragraphs
  by design.
