## Design

Fixes, each traced to a review/verify record item
(reviews/round1.yaml; verify failed_items):

1. **Code-block overflow (d6a6bae72f921952)**: the code-block element's
   inline style additionally declares horizontal scrolling on overflow
   (DESIGN.md decision).
2. **List/code typography (782a6b825666b592)**: list items render at the
   body token (16px / 1.8 line-height / on-surface #232A31) and code blocks
   carry the on-surface text color, matching the mockup. Mechanism: declare
   the body typography explicitly on the elements themselves (mail clients
   are unreliable about inheritance); the body wrapper in the digest
   template may ALSO carry the body typography as a fallback layer, per the
   mockup's structure.
3. **Fence-line content preservation (4d6b56426c1d3658)**: an OPENING fence
   may carry an info string (which is discarded); a CLOSING fence is only a
   line whose content is the fence marker plus optional whitespace. Inside
   an open block, a fence-marker line with trailing text is block content.
   Outside a block... a fence-marker line with trailing text opens a block
   (info string). No input text is ever silently dropped (FR1 "never
   dropped").
4. **Parenthesized link URLs (747d0a8adb3356cb)**: the link-destination
   parser accepts balanced parentheses inside the URL (e.g.
   `https://example.com/a(b)`); when the destination cannot be terminated
   (unbalanced), the whole construct falls back to escaped plain text.

No signature changes; renderer stays package-private, stdlib-only (NFR1);
escape-before-markup unchanged (NFR2).
