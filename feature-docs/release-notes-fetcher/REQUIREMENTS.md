# Claude Code リリースノート定期取得・日本語化メール配信 - 要件定義書

## 1. 概要

### 1.1 背景
Claude Code のリリースノートは GitHub (`anthropics/claude-code`) の Releases で英語で公開されている。更新を手動で追いかけるのは手間であり、日本語で読みたい。

### 1.2 目的
リリースノートを定期的に自動取得し、日本語化した HTML メールで受け取れるようにする。

### 1.3 スコープ
- 単発実行の Go 製 CLI バイナリ（スケジューリングは systemd timer に委譲）
- GitHub Releases API からの差分取得、claude-batch による日本語化、Gmail SMTP での HTML メール送信
- systemd user unit のサンプルテンプレート同梱
- スコープ外: Web UI、複数宛先管理の高度な機能、リリースノート以外の情報配信

## 2. ビジネス要件

### 2.1 ビジネス目標
Claude Code の更新情報を日本語で漏れなく受動的に受け取れる状態にする。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| 本人（単一ユーザー） | 自分のマシンで systemd timer により定期実行し、自分のメールアドレスで受信する |

### 2.3 期待される効果
- リリースノートの見逃し防止
- 英語読解の手間削減

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | 定期実行での差分配信 | systemd timer | 高 |
| UC02 | 初回実行 | ユーザー | 高 |
| UC03 | 手動実行 | ユーザー | 中 |

### 3.2 ユースケース詳細

#### UC01: 定期実行での差分配信

**アクター**: systemd timer（6時・12時・18時 JST）

**事前条件**:
- 設定ファイル（Gmail 認証情報・宛先・GitHub トークン）が配置済み
- 状態ファイルに前回取得済みバージョンが記録済み

**基本フロー**:
1. 状態ファイルから取得済み最新バージョンを読む
2. GitHub Releases API の先頭 1 ページのみを取得し、semver 比較で新しいものだけを選ぶ
3. 新規リリースがなければ何もせず正常終了する
4. 未取得分すべてをまとめて claude-batch に 1 回で日本語化依頼する
5. HTML メールを構築し（新しいバージョンを先頭に）、Gmail SMTP で 1 通送信する
6. 状態ファイルを、その実行で配信したリリースのうち semver 上で最大のタグ名に更新する

**代替フロー**:
- GitHub 取得・claude-batch・メール送信のいずれかが失敗した場合: 状態ファイルを更新せず、エラーを stderr に出力して非ゼロ終了する（次回実行時に自動リトライされる）

**事後条件**:
- 状態ファイルが、配信したリリースのうち semver 上で最大のタグ名を指している

#### UC02: 初回実行

**アクター**: ユーザー

**事前条件**: 状態ファイルが存在しない

**基本フロー**:
1. 状態ファイルが無いことを検出する
2. draft・prerelease・パース不能なタグを除外したうえで選ばれる 1 件のみを取得する
3. 日本語化してメール送信する
4. 状態ファイルを作成し最新バージョンを記録する

**事後条件**: 状態ファイルが作成されている

#### UC03: 手動実行

コマンドを直接実行する。挙動は UC01/UC02 と同一。

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | リリース差分取得 | GitHub Releases API から未取得リリースを取得 | 高 |
| F02 | 状態管理 | 配信分のうち semver 上で最大のタグ名を XDG state に保存 | 高 |
| F03 | 設定読み込み | YAML 設定ファイルの読み込みと検証 | 高 |
| F04 | 日本語化 | claude-batch へまとめて 1 回で翻訳依頼 | 高 |
| F05 | HTML メール構築・送信 | 1 通の HTML メールを Gmail SMTP で送信 | 高 |
| F06 | systemd unit テンプレート | .service / .timer のサンプル同梱 | 中 |

### 4.2 機能詳細

#### F01: リリース差分取得

**説明**: `anthropics/claude-code` の GitHub Releases API の先頭 1 ページのみを取得し、保存済みバージョンとの semver 比較で新しいリリースだけを収集する。保存済みバージョンが一覧から削除されていても正常系として扱い、比較で新しいものだけを返す。初回（状態ファイル無し）は、パース可能で draft・prerelease でない最新の 1 件のみ。

**入力**: 保存済みバージョン（または無し）、GitHub トークン
**出力**: リリースのリスト（tag_name, body, published_at）

**ビジネスルール**:
- 認証は Personal Access Token 必須（設定ファイルに記載）
- draft / prerelease は対象外とする

**エラーケース**:
| エラー | 条件 | 対応 |
|--------|------|------|
| API エラー | HTTP 失敗・レート制限 | 状態未更新で非ゼロ終了 |

#### F02: 状態管理

**説明**: `~/.local/state/claude-release-notes/`（`$XDG_STATE_HOME` 準拠）に、配信分のうち semver 上で最大のタグ名を保存する。更新はメール送信成功後のみ。

#### F03: 設定読み込み

**説明**: `~/.config/claude-release-notes/config.yaml`（`$XDG_CONFIG_HOME` 準拠）から Gmail 認証情報（アカウント・アプリパスワード）・宛先・GitHub トークンを読む。必須項目欠落時はエラー終了。

#### F04: 日本語化

**説明**: `claude-batch -` を起動し、stdin に「日本語化指示 + 未取得リリースノート原文（全件まとめ）」を流し、stdout から訳文を受け取る。呼び出しは 1 回。

**エラーケース**: claude-batch が非ゼロ終了、または応答が空の場合はエラー終了（状態未更新）。

#### F05: HTML メール構築・送信

**説明**: 未取得分すべてを 1 通の HTML メールにまとめ、新しいバージョンを先頭に並べて Gmail SMTP（smtp.gmail.com、アプリパスワード認証）で送信する。デザインは design ステップで決定する。

#### F06: systemd unit テンプレート

**説明**: user unit（`systemctl --user`）用の `.service` / `.timer` サンプルをリポジトリに同梱する。`OnCalendar=*-*-* 06,12,18:00:00 Asia/Tokyo`、`Persistent=true`。README にインストール手順を記載する。

## 5. 非機能要件

### 5.1 パフォーマンス要件
- 軽量 I/O バッチであり、明示的な性能目標は設けない

### 5.2 セキュリティ要件
- 認証情報（Gmail アプリパスワード・GitHub トークン）は設定ファイルのみに保持し、ログ・エラー出力に含めない
- SMTP は TLS 経由で接続する

### 5.3 可用性要件
- 失敗時は状態を更新せず終了し、次回定期実行で自動リトライされる（At-least-once 配信）

### 5.4 保守性要件
- ログ出力: stdout/stderr のみ（systemd 実行時は journal で確認）
- 依存最小: YAML パーサ以外は Go 標準ライブラリで実装

### 5.5 互換性要件
- Linux（systemd 環境）で動作すること

## 6. UI/UX要件

### 6.1 画面設計要件
HTML メールのレイアウト・配色・タイポグラフィは design ステップで決定する。要件レベルでは以下のみ規定する:
- 複数リリースを 1 通に含め、新しいバージョンを先頭に表示する
- 各リリースはバージョン（タグ名）・公開日・日本語化された本文を含む

### 6.2 画面遷移
N/A（メールのみ）

### 6.3 レスポンシブ対応
一般的なメールクライアント（モバイル含む）で崩れず読めること。

## 8. 外部連携

### 8.1 連携システム
| システム名 | 連携方法 | データ |
|------------|----------|--------|
| GitHub Releases API | HTTPS (REST, token 認証) | リリース一覧 JSON |
| claude-batch | サブプロセス（stdin/stdout） | 翻訳プロンプト / 訳文 |
| Gmail SMTP | smtp.gmail.com (TLS, アプリパスワード) | HTML メール |

### 8.2 API仕様要件
- GitHub: 差分取得（`Since`）は `GET /repos/anthropics/claude-code/releases` の先頭 1 ページのみを取得する
- GitHub: `GET /repos/anthropics/claude-code/releases`（ページング対応）

## 10. 想定される課題とリスク

### 10.1 技術的課題
| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| 未取得分が多い場合に claude-batch の応答が長大化 | 中 | 差分取得は先頭 1 ページのみを読むため、1 実行が扱う件数は per-page の上限で有界 |
| Gmail アプリパスワードの失効 | 中 | 失敗時は状態未更新のため、再設定後の実行で回復 |

## 12. テストシナリオ

### 12.1 テスト観点
- [ ] 正常系: 差分取得 → 翻訳 → メール構築 → 状態更新の一連のフロー（モック使用）

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| claude-batch | プロンプトを渡すと Claude の応答テキストを stdout に返すローカルコマンド（`/usr/bin/claude-batch`）。引数 `-` で stdin からプロンプトを読む |
| 状態ファイル | 直近の実行で配信したリリースのうち semver 上で最大のタグ名を記録するファイル |
