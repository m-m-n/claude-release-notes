# Task Plan: task0005 — HTML digest build and Gmail SMTP send

## Goal

A `mail` package that composes the Japanese release-notes digest as a
self-contained HTML email and sends it through Gmail SMTP.

## Requirements

FR5, NFR2

## Scope

### Files to Create
- `internal/mail/build.go` — digest item type, subject and HTML body
  composition
- `internal/mail/build_test.go` — unit tests
- `internal/mail/send.go` — SMTP sender (STARTTLS, AUTH, MIME assembly)
- `internal/mail/send_test.go` — unit tests
- `go.mod` — only if absent in the worktree, per IMPLEMENTATION.md "Module
  identity" (standard library only)

### Files to Modify
- (none)

## Design

Implements the `mail.Build(items)` and `mail.Sender` contracts in
IMPLEMENTATION.md Shared Components.

### Build

1. Input items are ordered newest first (caller's responsibility; Build
   preserves order). Each item: version tag, publish date, translated body
   text.
2. Subject: `Claude Code リリースノート: {newest version} ほか {N-1} 件`;
   with a single item, just `Claude Code リリースノート: {version}`.
3. HTML body — visual intent from the design step, expressed with literal
   values from `design-system/tokens.yaml` (mail clients do not support CSS
   custom properties, so every style is an inline `style=""` attribute; no
   `<style>` block reliance, no external resources, no web fonts —
   `system-ui, sans-serif` stack):
   - Single centered column, max width 600px, on the canvas background
     `#F4F1EC`; content sits on one white (`#FFFFFF`, token surface) card
     with a 1px `#E4DED4` (divider) border.
   - Header band: primary `#C15F3C` background, white (on-primary) text —
     the mail title "Claude Code リリースノート" at 20px/1.4 bold
     (heading-mail) plus a caption line
     "anthropics/claude-code · {N} 件の新しいリリース" at 13px (caption).
   - Per release section: version tag as an 18px/1.4 bold heading in primary
     `#C15F3C` (heading-release); publish date below it at 13px in muted
     `#6E675E` (caption / on-surface-muted) formatted as a date with an
     explicit-timezone-unambiguous day (e.g. `2026-07-16 公開`); translated
     body at 16px/1.8 (body) in `#2B2620` (on-surface). Sections separated
     by a 1px `#E4DED4` divider rule. Spacing in multiples of 8px (spacing
     unit).
   - Empty body item renders `（リリースノート記載なし）` in muted
     `#6E675E` instead of an empty section.
   - Footer: caption line "claude-release-notes により自動送信 · 原文:
     GitHub Releases" in muted, above nothing else.
4. Body text is HTML-escaped via auto-escaping templating; translated text
   is treated as plain text with line breaks preserved as paragraph/line
   breaks.

### Send

1. Sender is constructed with host, port, account, app password; defaults
   target Gmail's submission endpoint on port 587 with STARTTLS then SMTP
   AUTH.
2. Message assembly: RFC-compliant headers (From, To, Subject, MIME-Version,
   Content-Type `text/html; charset=UTF-8`, Date); subject MIME-encoded for
   UTF-8; body transfer-encoded safely for non-ASCII content.
3. Errors never include the app password.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Build renders every item, in given order, each with version,
      date, and body; N-item and 1-item subjects follow the specified
      formats.
- [ ] AC-2: HTML metacharacters in translated text appear escaped in the
      output; no raw injection is possible.
- [ ] AC-3: An empty body item renders the placeholder text instead of an
      empty section.
- [ ] AC-4: The rendered HTML uses only inline style attributes (no <style>
      block, no external URLs) and contains the header band, divider rules,
      and footer.
- [ ] AC-5: The assembled message has correct MIME headers, a UTF-8-encoded
      subject, and a body that decodes back to the HTML.
- [ ] AC-6: Send performs STARTTLS and AUTH against a mocked/injected SMTP
      endpoint and errors from it never contain the password (sentinel
      assertion).

## Test Notes

Build tests are pure golden-ish assertions on the produced HTML/subject.
Send tests use a local mock SMTP conversation or an injected dial seam — no
real SMTP. AC-2/AC-3 come straight from SPEC edge cases.

## Out of Scope

- Choosing which releases go into the digest and when to send (task0006).
- Retry logic (none by design — NFR4).
