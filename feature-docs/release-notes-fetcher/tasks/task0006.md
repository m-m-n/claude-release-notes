## Design

Consumes every contract in IMPLEMENTATION.md Shared Components through
interfaces declared in `internal/app` (consumer-side interfaces decision).

Pipeline (the order IS the contract — NFR4):

1. Load config; failure → abort.
2. Load state. Found → fetch releases newer than the stored version; not
   found (first run) → fetch only the latest release (FR2 / SPEC US2).
3. Zero new releases → log "no new releases" to stdout and finish
   successfully WITHOUT translating, sending, or saving (TS-7).
4. Translate all bodies in one call (order preserved, newest first).
5. Build the digest from versions, publish dates, and translations; send it.
6. Only after a successful send: save the newest version to state (FR2,
   NFR4). Save failure → error exit (send already happened; next run may
   re-send — at-least-once is accepted).
7. Any step's failure → wrap with the stage prefix (Conventions), print to
   stderr at the entry point, exit 1. Success paths exit 0.

Logging (NFR3): one stdout progress line per stage with counts (e.g. fetched
N releases); timestamps, when printed, carry an explicit timezone. Secrets
never logged (NFR2 — enforced by never logging config values at all).

Entry point: no flags; construct config/state with empty base dirs (XDG
defaults per contracts), the GitHub client with the configured token, the
translator with the default command name, the sender with Gmail defaults.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: First run (state not found) processes exactly the latest release
      and saves its version after a successful send.
- [ ] AC-2: Subsequent run fetches only releases newer than the stored
      version and saves the newest delivered version after sending.
- [ ] AC-3: Zero new releases → success exit, and neither translator, mail,
      nor state save is invoked (mock call assertions).
- [ ] AC-4: Failure injected at each stage (fetch / translate / send) →
      pipeline returns an error carrying that stage's prefix and state save
      is NEVER invoked.
- [ ] AC-5: Releases flow to the mail builder newest first with translations
      aligned to their releases.
- [ ] AC-6: Progress logging goes to stdout and error output to stderr
      (asserted via injected writers); any timestamp in output includes a
      timezone designation.
- [ ] AC-7: go.mod requires no third-party module other than the YAML
      parser (NFR1; asserted by inspecting the module file in the worktree).
