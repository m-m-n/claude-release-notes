# Task Plan: task0001 — Config loading and validation

## Goal

A `config` package that loads and validates the tool's YAML configuration
from the XDG config directory, so every other component receives verified
credentials and addresses.

## Requirements

FR3, NFR2

## Scope

### Files to Create
- `internal/config/config.go` — config struct, XDG path resolution, YAML
  loading, validation
- `internal/config/config_test.go` — unit tests
- `go.mod` — per IMPLEMENTATION.md "Module identity" (this task imports
  gopkg.in/yaml.v3)
- `go.sum` — module checksums for yaml.v3

### Files to Modify
- (none)

## Design

Implements the `config.Load(baseDir)` contract in IMPLEMENTATION.md Shared
Components. Behavior:

1. Resolve the config file path: `{baseDir}/config.yaml`; when baseDir is
   empty, use the XDG config home (environment override, falling back to the
   home-relative default) plus `claude-release-notes/`.
2. Parse the YAML keys `gmail.account`, `gmail.app_password`, `mail.to`,
   `github.token` (structure per SPEC.md "Database Schema" section).
3. Validate: every key present and non-empty; the error message names the
   offending key (e.g. "gmail.app_password") and NEVER contains the value.
4. File unreadable / YAML malformed → error with the file path (path is not
   a secret).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A valid config file parses into a Config whose four fields match
      the file's values.
- [ ] AC-2: For EACH required key, a config missing that key (and a config
      with the key empty) yields an error whose message contains the key name.
- [ ] AC-3: No error message produced by the package contains a configured
      secret value (asserted against a sentinel value in tests).
- [ ] AC-4: With a non-empty baseDir, no environment variable or real home
      directory is consulted (tests run against t.TempDir()).
- [ ] AC-5: XDG resolution: with the XDG config-home environment variable
      set, the path under it is used; unset, the home-relative default is
      used.

## Test Notes

All criteria are unit tests with temp dirs (test/README.md patterns). AC-5
uses environment manipulation helpers scoped to the test. No network.

## Out of Scope

- State file handling (task0002), any consumption of the Config (task0006).
- Config file creation/scaffolding — the tool never writes config.
