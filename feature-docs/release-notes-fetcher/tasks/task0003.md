# Task Plan: task0003 — GitHub Releases client

## Goal

A `github` package that fetches `anthropics/claude-code` releases via the
GitHub REST API with token auth, exposing a "latest release" query that
returns the newest deliverable release under its full filter, and a
"releases newer than X" query bounded to the first listing page.

## Design

Implements the `github.Client` contract in IMPLEMENTATION.md Shared
Components. Behavior:

1. Endpoint: the releases listing for `anthropics/claude-code`
   (`/repos/anthropics/claude-code/releases`) with per-page sizing and page
   parameters; base URL injectable so tests point at a local test server.
2. Every request carries the token as a Bearer authorization header and the
   GitHub JSON Accept header.
3. Fields consumed per release: tag name, body, published-at, draft,
   prerelease. Draft and prerelease entries are filtered out everywhere; the
   latest-release query additionally excludes entries whose tag does not
   parse, the same rule the differential query already applies.
4. `Latest()`: first entry in the listing (API returns reverse-chronological
   order) that is not a draft, not a prerelease, and whose tag parses as
   `vMAJOR.MINOR.PATCH`; none found after exhausting pagination → error.
5. `Since(version)`: issue one request for the first listing page only
   (never walks pagination). The stored version must parse as
   `vMAJOR.MINOR.PATCH`; an unparseable stored version is an error naming
   the offending value. Collect filtered releases whose tag name compares as
   a newer semantic version than the stored version (unparseable listing
   tags are skipped); a stored version absent from the listing is a normal
   case where only the releases that compare newer are collected. Result is
   newest first.
6. Non-2xx response → error including the HTTP status but never the token.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Since returns exactly the releases that compare newer than the
      stored version, newest first, across a single-page mocked listing.
- [ ] AC-2: Draft and prerelease entries never appear in Latest or Since
      results.
- [ ] AC-3: Since with the stored version as the newest listing entry
      returns an empty slice.
- [ ] AC-4: Since with a stored version absent from the listing returns only
      the listed (filtered) releases that compare newer, not the whole
      listing.
- [ ] AC-5: Latest returns the newest release filtered by draft, prerelease,
      and parseability.
- [ ] AC-6: Requests carry the Bearer token and Accept headers (asserted by
      the mock server).
- [ ] AC-7: A non-2xx API response yields an error containing the status
      but not the token value.

## Test Notes

Unit tests with a local HTTP test server serving canned paged JSON; no real
network. For Since, the core case is that only the first page is requested
(AC-1); the multi-page canned data remains meaningful for Latest, which
still walks pagination. AC-7 uses a sentinel token value asserted absent
from the error text.
