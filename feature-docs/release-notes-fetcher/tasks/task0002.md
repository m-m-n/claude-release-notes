# Task Plan: task0002 — Last-version state store

## Goal

A `state` package that persists the last delivered release version in the
XDG state directory, with atomic writes and a clean "no state yet" signal
for first runs.

## Requirements

FR2

## Scope

### Files to Create
- `internal/state/state.go` — store type, XDG path resolution, load/save
- `internal/state/state_test.go` — unit tests
- `go.mod` — only if absent in the worktree, per IMPLEMENTATION.md "Module
  identity" (this task needs no third-party imports)

### Files to Modify
- (none)

## Design

Implements the `state.Store` contract in IMPLEMENTATION.md Shared
Components. Behavior:

1. Store file: `{stateDir}/state.json` holding the last delivered
   `tag_name` (format per SPEC.md: a single `last_version` field). Empty
   stateDir → XDG state home (environment override, home-relative fallback)
   plus `claude-release-notes/`.
2. `Load`: file absent → (found=false, no error). File present → the stored
   version. Corrupt/unreadable file → error (distinct from absence).
3. `Save(version)`: write via temp file + rename in the same directory;
   create missing directories first. Post: a concurrent reader sees either
   the old or the new content, never a partial write.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Save then Load round-trips the version string.
- [ ] AC-2: Load on a directory with no state file reports found=false
      without error.
- [ ] AC-3: Load on a malformed state file reports an error.
- [ ] AC-4: Save creates the state directory when it does not exist.
- [ ] AC-5: Save leaves no temp-file residue and the final file contains
      exactly the new content (rename-based atomicity observable via
      directory listing).
- [ ] AC-6: XDG resolution: with the XDG state-home environment variable
      set, the path under it is used; unset, the home-relative default is
      used.

## Test Notes

All unit tests against t.TempDir(). AC-5 checks the directory afterwards for
leftover temp names. No concurrency test needed (single process by design).

## Out of Scope

- Deciding WHEN to save (that ordering lives in internal/app, task0006).
- Config handling (task0001).
