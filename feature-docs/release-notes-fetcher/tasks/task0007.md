# Task Plan: task0007 — systemd unit templates and README

## Goal

Sample systemd user units that run the tool at 06/12/18 JST with catch-up,
plus a README covering setup end to end.

## Requirements

FR6

## Scope

### Files to Create
- `systemd/claude-release-notes.service` — oneshot user service template
- `systemd/claude-release-notes.timer` — calendar timer template
- `README.md` — project overview, build, configuration, Gmail app-password
  setup pointer, systemd installation instructions

### Files to Modify
- (none)

## Design

1. Service unit: oneshot type, executing the installed binary (document the
   expected install path and how to adjust it). No scheduling content in the
   service unit itself.
2. Timer unit: `OnCalendar=*-*-* 06,12,18:00:00 Asia/Tokyo`,
   `Persistent=true` (catch-up after sleep/downtime), tied to the service
   unit; installable via user-level systemd.
3. README (Japanese): what the tool does; build step (the approved build
   command); config file location
   (`~/.config/claude-release-notes/config.yaml`), full key reference with a
   redacted example, and the instruction to restrict permissions to owner
   read/write only (chmod 600 — NFR2); state file location; Gmail
   app-password acquisition pointer; GitHub token requirement; unit
   installation steps (copy to the user unit directory, daemon-reload,
   enable --now the timer) and how to check runs via journalctl; manual-run
   instructions.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The timer unit contains exactly the specified OnCalendar
      expression and Persistent=true.
- [ ] AC-2: The service unit is a oneshot referencing the binary, and the
      timer references the service.
- [ ] AC-3: README documents: build, config path + all four config keys,
      chmod 600 instruction, state path, systemd install/enable steps, and
      journalctl inspection.

## Out of Scope
