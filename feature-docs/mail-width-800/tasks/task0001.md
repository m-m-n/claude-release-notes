# Task Plan: task0001 — Digest container width 800px

## Goal

The generated digest email HTML constrains its content card to a maximum
width of 800px (previously 600px), matching the design SSOT.

## Requirements

FR1, NFR1

## Scope

### Files to Create

- None.

### Files to Modify

- `internal/mail/build.go` — the digest template's outer container inline
  style changes its maximum-width value from 600px to 800px. No other style
  value changes.
- `internal/mail/build_test.go` — assert the generated HTML contains the
  800px maximum-width declaration and no 600px one; keep existing
  assertions intact.
- `internal/mail/markdown_test.go` — a comment mentions the "600px mail
  column"; update the wording to 800px (comment accuracy only, no test
  behavior change).

## Design

The digest template inlines literal design-token values as `style=""`
attributes (mail-client constraint; see IMPLEMENTATION.md Conventions).
This task updates exactly one literal: the outer container's maximum width.
The `max-width` semantics are preserved so narrow clients continue to
reflow to a single narrower column.

Precondition: design SSOT records 800px
(`feature-docs/release-notes-fetcher/DESIGN.md`).
Postcondition: generated digest HTML declares a 800px maximum width on the
outer container and nowhere declares 600px.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The HTML produced by the digest builder contains the 800px
  maximum-width declaration on the outer container.
- [ ] AC-2: The HTML produced by the digest builder contains no 600px
  maximum-width declaration.
- [ ] AC-3: All pre-existing `internal/mail` tests pass unchanged in
  behavior (subject composition, body rendering, escaping).

## Test Notes

- AC-1 / AC-2 translate to string assertions on the builder's output in the

- AC-3 is the existing suite acting as the regression net; no test may be
  weakened or deleted.
- TDD-awkwardness: none — assertions are direct string checks.

## Out of Scope

- The mockup HTML and DESIGN.md (design artifacts are already updated).
- README or documentation changes.
